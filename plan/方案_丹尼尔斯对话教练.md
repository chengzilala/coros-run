## 0 一句话

把看板上「**一键出四段**」的 AI 复盘，扩展为一个**独立的、可多轮追问的丹尼尔斯体系专属教练**：读我们**已算好**的训练数据（五区配速 / 状态灯 / 强度占比 / 周报 / 负荷），按需注入**自撰**的伤病 / 营养知识，直接回答「**我下一步 / 下周该怎么练**」。

不是"给通用模型贴一句教练人设"，而是**方法论驱动 + 数据接地 + 确定性算术不交给 AI** 的专属角色。

## 2 目标（用户目标 / 输入输出 / 成功标准）

- **用户目标**：打开一个对话框，像跟真人教练一样连续问，并能立刻得到"下一步练什么"的可执行答案。
- **输入**：用户自然语言 ＋（自动拼入）已算好的训练上下文 ＋（按需）知识卡片段。
- **输出**：Markdown 回答（复用看板现有 `CorosUI.md()` 渲染），含**结论 / 依据（引用具体数字） / 行动项**。
- **成功标准**：
  1. 能连续追问**不失忆**（多轮上下文生效）；
  2. 回答**只引用我们算好的数字**，不心算、不臆造（缺数据就明说）；
  3. 伤病问题给**分级 + 降级建议**并标「仅供参考、非医疗」；
  4. 营养/补给能给**可执行数字**（由纯函数算出）。

## 4 架构（本机优先）

```
[web/coach.html + coach.js 对话框]
   │  ① 用户消息 + 历史 messages[] 一起 POST
   │  ② 自动拼「训练上下文」（复用 build_context 摘要）
   │  ③ 营养问题：前端纯函数先算好数字，只喂结果
   ▼
本机 web/serve.py 新增  POST /api/coach
   │  （用账户托管的 Key；与 /api/review 同源）
   ▼
【教练 system prompt】
  = 丹尼尔斯方法论规则集（周期化 / 80-20 / 10% 递增 / 红旗降级）
  + 人格风格（A/B/C/D）
  + 硬准则（无数据不推断、确定性算术不交给 AI、非医疗仅供参考）
【训练上下文】已算好的数字摘要
【知识注入】按关键词命中 → 追加对应知识卡文本
   ▼
OpenAI 兼容 /chat/completions → 流式或整段返回
```

**要点**：
- **零第三方依赖**：对话框、Markdown 渲染、知识路由全部原生实现，不引任何库；用本地现有 `echarts`/`ui.js` 之外的纯 JS。
- **确定性算术不交给 AI**：五区配速 / 状态灯 / 负荷 / 占比 / 营养数字都在前端或已有模块算好，作为上下文喂入；prompt 明确要求"只复述、不重算"。
- **知识路由**（不引向量库）：用关键词命中把相关卡片文本**注入同一条消息**（如「膝盖/髌骨/上下楼」→ 注入跑者膝卡）。
- **多轮上下文**：客户端持有 `messages[]`（含 system），每轮整段上送；**服务端无状态**（进度快、易上云）。
- **记忆沉淀**（远期，非本期）：跨会话长期记忆留待后续评估。

## 6 硬约束与红线（沿用项目规则）

1. **只读**：高驰官方 MCP 只读，教练**只出建议 / 文档**，**不回写手表**（课表推不到表，只做页面内呈现）。
2. **零第三方依赖**：前端原生；后端仅 Python 3 标准库。
3. **本机 Python 3.9.6**：若计算放后端须避开 3.10+ 语法（`float | None` 等）；**优先放前端纯函数**以规避且双端一份逻辑。
4. **合规**：伤病 / 营养属健康建议，**不做医疗诊断**，结论**必须标「仅供参考」**。
5. **隐私**：Key / token / 训练数据**只存本机、不入库、不写日志**；不新增第三方统计。
6. **不臆造**：无数据就说「数据不足」，不常识外推（沿用 §14.4 两条硬准则）。

## 9 δ 扩展：跑步万能人（2026-10-13）

**背景**：见 [可行性分析_跑步万能人.md](./可行性分析_跑步万能人.md)。结论＝**在现有教练上扩展、暂不接联网**。

**改了什么**
- 教练定位从「丹尼尔斯教练」扩为「专属跑步教练兼**跑步万事通**」，系统提示词改为**四类问题分工**：
  - ① 自身训练类——引用看板算好的数字（沿用丹尼尔斯内核，不重算）；
  - ② 通用知识类（训练原理 / 配速心法 / 装备 / 饮食常识）——放开，用模型自身知识直接答；
  - ③ 事实 / 赛事类——**优先引用下方已核验知识卡**并注明来源；未命中可凭知识答但须说明「未核验」；
  - ④ 实时信息类——**如实说明「我目前没有联网」**并给官方查询渠道，**绝不编造**。
  - 硬准则②由「无数据不推断」调整为「**不编造具体事实**」（放开通用知识，但纪录 / 成绩 / 日期等可查证事实仍不下无依据的断言）。
- 新增 **2 张「已核验事实」知识卡**（复用现有关键词路由，上限仍是 2 张 / 2600 字）：
  - `tools/coach_knowledge/facts_world_records.md`（世界纪录速查） ↔ 云端 `lib/knowledge.js` 内联副本
  - `tools/coach_knowledge/facts_events.md`（赛事评级·大满贯·选手等级） ↔ 云端同副本
  - 内容取自项目既有「跑步知识库」（F35，附官方来源）；为**快照，已标注「截至 2026-10」**。
- 知识参考横幅文案统一为「**已核验知识参考**（自撰/整理，仅供一般性参考；健康内容非医疗诊断…）」。

**改动文件**
- `web/serve.py`：`COACH_METHODOLOGY` 改写、`route_knowledge` 横幅、`KNOWLEDGE_DIR` 注释
- `cloud/functions/coach/lib/prompt.js`：`COACH_METHODOLOGY` 同步
- `cloud/functions/coach/lib/knowledge.js`：`CARDS` 前置两张事实卡 + 横幅统一

**验证**
