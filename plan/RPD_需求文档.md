> v0.51（2026-10-13）：**修看板图表「错乱」——同行卡片显隐后图表仍按旧宽度绘制**。用户反馈看板「训练负荷」与「强度分布」两张卡片图例/坐标轴错位重叠。**根因**：`renderCharts()` 里各卡片按序渲染时会「显隐」卡片（如 `renderIntensity` 把「强度分布」由 `hidden` 变可见），使同一行的「训练负荷」由**整宽变半宽**；而 ECharts 只在 `init` 时量一次容器宽度，卡片宽度随后变化**不会自动跟随**，画布仍按旧（整宽）尺寸绘制、溢出到相邻卡片，两图图例在中间重叠。**修法**（`web/app.js`）：在 `renderCharts()` 末尾对全部图表补一次 `resize()`，按**最终布局**重算尺寸；`bindTheme` 的热重绘路径卡片显隐已稳定、无需额外处理。**为什么不在每处显隐后各自 resize**：统一在批次末尾重算更简单，且天然覆盖后续新增的「显隐卡片」。**待部署**：仅前端静态资源（已随本次发布上线）。

## 1 项目概述

- **定位**：把**智能手表（高驰 COROS / 佳明 Garmin）**的训练数据，做成**自己看得顺眼**的数据看板 + **中文 AI 复盘**。
  起因：官方 App/网页的数据展示形式不友好、不是自己想要的；且多品牌数据割裂，想用**一套看板**统一看。
- **品牌范围（v0.25 起）**：**高驰 + 佳明**双品牌。高驰已跑通（现状，见下），**佳明为新增规划**（见 §16）；两者功能**对等**，并吸收参考项目里高驰没有的维度（如身体电量）。佳明的对手链接：见 `inbox/备忘录`。
- **目标用户**：第一版**只有我自己**（本机运行）。对外版本（官网/H5/小程序）留待后续阶段。

## 3 详细功能需求

- **F1 授权**：浏览器 OAuth（PKCE），本地回调 `127.0.0.1:8765`；按账号区域选端点（`cn`/`us`/`eu`）；凭据存 `.coros_token*.json`（gitignored）。
- **F2 抓数**：`--details N` 控制抓取最近 N 次的详细数据；解析 MCP 返回（注意文本二次编码）；产出 `web/data/dashboard.json`。
- **F3 看板**：KPI＝最近 30 天跑量 / 累计跑量 / 平均配速 / 平均心率；三图＝按月跑量、近 40 次配速·心率、训练负荷短期/长期。
- **F4 详情**：弹窗展示距离/用时/配速/心率/步频/功率/步幅/爬升/消耗/负荷/有氧效果/训练重点 + 分段图。
- **F5 AI 复盘**：两种口径（整体 / 只看最近一次）；固定四段输出；**只用真实数据**，不足则说明。
- **F6 我的账户**：服务商预设 + 地址/Key/模型三字段 + 显示隐藏 Key + 测试连接 + 保存 + 清除托管 Key + 外观（跟随系统 / 按时间 / 黑夜 / 白天）+ 字号；Key **平时掩码显示**（点「显示」按需 `keyReveal` 取一次本人明文，点「隐藏」即清），**加密托管在本机**（不再写明文文件）。
- **F10 账户体系（本机版原型）**：账户码＝32 位十六进制随机串（账号 + 登录凭证一体），首次访问自动生成本机唯一持有；本机只存账户码/掩码/昵称，Key 明文不落本机只交本机服务加密托管；跨设备登录支持「6 位一次性码」与「粘贴账户码」；退出登录走站内弹层**先展示完整账户码再退出**（防呆）。结构 1:1 对齐对外版（微信读书插件），将来换云函数只改 endpoint + 加密函数。
- **F11 H5/网页交互增强**：轻量 `ui.js`（`esc` / `toast` / `copyText` 带降级 / `stateHtml` 三态 / 站内确认弹层 `confirmDialog`）；`store.js` 统一本机键（账户码/掩码/昵称/带 TTL 缓存/字号档位/外观主题）；PWA「加到桌面」（manifest + 图标 + 直通 Service Worker，不做离线缓存以免看到旧文件）。
- **F25 佳明支持**：新增佳明数据源，功能与高驰**对等**——授权/绑定、抓数、看板、单次详情、AI 复盘、看板增强全部适用。两条品牌数据**分别入库、互不混用**；恢复类指标（就绪度等）须**同源**，不跨品牌混算（避免基线漂移）。
- **F26 数据源适配层**：定义**统一内部数据模型**（活动 / 每日指标 / 用户资料 / 恢复状态），高驰与佳明各实现一个**适配器**（负责授权 + 抓数 + 字段映射到统一模型）；业务层（看板 / 详情 / AI）只认统一模型，**加设备＝加适配器**。
- **F27 身体电量**：佳明 Body Battery（能量）；作为「今日状态灯」的一个信号——佳明有则并入、高驰无则计入 `skipped`，**绝不臆造**。
- **F28 真 ACWR**：佳明自带 ACWR **直接采用**；高驰沿用官方 Load Ratio。看板统一展示为「负荷比」，并**标注来源**（Garmin ACWR / COROS Load Ratio）。
- **F32 地点分布（地图维度）**：每条活动带 `coordinates`（WGS-84）。① **跑步机（`sportType 101`）单列**；② 其余在**本机按 0.01°（≈1.1 公里）坐标聚类**成一个「点」；③ 每个点用**离线行政区划**（`web/data/cn_regions.json`，DataV.GeoAtlas、GCJ-02）做 **WGS-84→GCJ-02 转换 + 最近邻匹配**，**自动得出「市 区县」**（如「黄石市 阳新县」）——**不再要求用户从经纬度手动猜城市**；④ 用户可把某点**覆盖成自定义名**（如「家附近」），**同名自动合并**；⑤ 可把某点标为「跑步机」（并入）或「忽略」（不计入）。展示为**占比环形图（top7 + 其他）+ 统计表**（地点 / 次数 / 距离 / 时长 / 占比）。自定义映射**存账户、跨设备**（本机 `/api/account` 的 `places`；线上云函数 `account` 的 `placesGet`/`placesSave`，`user_prefs` 集合）。**离线查表、坐标不出本机，绝不调用在线地图服务**；`location` 文字字段脏（296 条仅 67 条有值），仅作弹窗里的**记录地点提示**。
- **边界**：只读手表数据（**高驰 / 佳明**）；不上传；Key/token/训练数据一律不入库；**敏感文件（accounts.json / secret.key / llm_config.json）禁止被服务当静态资源返回**；AI 复盘失败要给出可读原因（未配置 / 接口报错）。

## 5 技术实现方案

- **前端**：原生 HTML/CSS/JS；图表用**本地** ECharts（`web/lib/echarts.min.js`，不走 CDN）；零构建。
  轻量模块：`store.js`（本机存储/主题/字号/缓存）、`ui.js`（toast/弹层/复制/三态）、`pwa.js`（注册 SW）、`account.js`（账户页）。
- **后端**：`web/serve.py`，**仅 Python 3 标准库**；提供静态发布 + `POST /api/review` + `GET/POST /api/account`（账户码/Key 加密托管/跨设备登录）。
  本机版应用层加密：`v1:<nonce>:<tag>:<ct>`（HMAC-SHA256 流加密 + 认证标签；与对外版 AES-256-GCM 同一密文外壳，可平滑替换）；机器密钥存 `web/data/secret.key`（chmod 600，自动生成、不入库、不写日志）。
- **数据链路**：`tools/source_coros.py`（高驰适配器：授权 + 抓取 + 解析，复用 `coros_probe.py` 传输层）→ 统一模型 → `tools/fetch_data.py`（公共编排/输出层，按 `--source` 选适配器）→ `web/data/dashboard.json`（本地数据）→ 前端渲染。加品牌＝加 `tools/source_<provider>.py`（由 `tools/adapters.py` 动态加载）。
- **数据源适配层（阶段十七·步 1 已实现）**：把现有高驰链路重构为「**适配器 + 统一模型**」——高驰 / 佳明各一个适配器（负责授权 + 抓数 + 字段映射），输出**统一内部模型**（活动 / 每日指标 / 资料 / 恢复），再走既有 `dashboard.json` 与前端渲染。**加品牌＝加适配器**，看板 / 详情 / AI 逻辑不动（详见 §16）。
- **大模型**：任何 OpenAI 兼容接口（`/chat/completions`）；**网页复盘严格只用账户托管的 Key**（`/api/account` 加密存取）——没配就给出「请先去我的账户配置」的可读提示，**不再退回** `web/llm_config.json` / 环境变量（避免界面显示「未配置」却偷偷用别处 Key）；`llm_config.json` / 环境变量仅供命令行/开发直连模块时使用。

## 8 风险与应对

| 风险 | 应对 |
| --- | --- |
| 账号区域选错导致认证失败 | 明确 `COROS_REGION` 三选一，README/Running 写清（本账号用 `us`） |
| MCP 返回格式变动（文本二次编码） | 解析集中在 `tools/source_coros.py` 的 `get_text/get_json_text`，易改 |
| 大模型 Key 泄露 | **用户自填 Key 走应用层加密托管**（AES-256-GCM，密钥由 `KEY_SECRET` 派生）、界面平时只显掩码、明文不写日志、不在页面常驻；仅当用户在账户页**主动点「显示」**时，服务端按 uid 校验后把**本人这份**明文回一次（`keyReveal`，用完即清）。平台 `LLM_API_KEY` 仅存控制台/本机 gitignored 配置，**绝不入库/不进代码库** |
| 接口/模型名变更 | 设置页可随时换服务商与模型，无需改代码 |
| 把「自用版」误当对外服务 | 项目规则「不可做」已写明：对外版需另建授权后端 |
| **佳明数据源待定**（无面向个人的官方开放 OAuth） | 先核实可行路径（官方 Health API / 非官方 Connect / 参考项目 MCP），选定后再写适配器（见 §16.2） |
| **佳明非官方库需第三方依赖** | 与本项目「零第三方依赖」红线冲突；若必须，仅限**本机抓数脚本**、**经用户明确批准后**才破例（见 §16.2） |
| **两品牌恢复指标口径不同** | 恢复类指标**同源不混算**；跨品牌不可比的项分别**标注来源**，不合并成一条数 |

## 10 账户体系落点（本机版原型，2026-10-09）

> 参照经验母本：`微信读书插件/plan/账户体系_说明.md`。心智一致：**账户码＝账号 + 登录凭证（一体）、本机唯一持有**。

| 项 | 本机版落点 |
| --- | --- |
| 账户码 | 32 位十六进制，浏览器首次访问生成（`store.js` `getDeviceId`），存 `localStorage` 键 `coros_account_id` |
| 服务端认人 | `web/data/accounts.json` 的 `users[账户码]`（本机 `serve.py` 充当中转） |
| Key 托管 | 应用层加密后存 `accounts.json.enc`（密文 `v1:<nonce>:<tag>:<ct>`），平时只回掩码；点「显示」按需 `keyReveal` 回一次本人明文 |
| 机器密钥 | `web/data/secret.key`（chmod 600，首次自动生成；也可用环境变量 `COROS_KEY_SECRET`） |
| 跨设备登录 | 6 位一次性码（10 分钟、用一次失效，存 `binds`）／粘贴 32 位账户码 |
| 退出防呆 | 站内弹层先展示完整账户码 + 一键复制，确认后才退出（`ui.js` `confirmSignOut`） |
| 清除托管 Key | 只清 `enc`/`masked`，保留账户与昵称 |

**接口**（`serve.py`）：`GET /api/account?device=`；`POST /api/account` 以 `action` 区分：`keySave` / `keyClear` / `profileSave` / `bindCreate` / `bindRedeem` / `test`。
**安全**：`accounts.json` / `secret.key` / `llm_config.json` 既不入库，也**禁止被静态下载**（服务端 403）。

## 11 对外版用户体系设计（v0.4 规划，2026-10-09）

> 目标：把「本机自用」升级为**对外开放的多用户产品**。核心变化＝引入**真正的用户体系**。
> 本机版账户原型（§10）是它的前身：升级时把「本机服务」换成**腾讯云开发 CloudBase**（云函数 + 云数据库 + 身份认证），**前端账户页可复用**。
> **为什么用国产**：用户**无国外网络访问环境**，故不用 Vercel / Supabase，改用同能力的**腾讯云开发 CloudBase**（一个平台含：静态托管 + 云函数 + 云数据库 + 邮箱验证码登录）。

### 11.1 两层账号（关键心智）

对外版有**两层账号**，别混为一谈：

| 层 | 是什么 | 登录方式 | 存哪 |
| --- | --- | --- | --- |
| **产品账号** | 用户登录「你的网站」的身份 | **邮箱验证码**（默认）或 **邮箱密码**（可选，用户在登录页设置一次） | CloudBase 身份认证 |
| **高驰授权** | 用户授权你读取他本人的高驰数据（只读） | 高驰 OAuth（动态注册 + PKCE） | 加密存云数据库（仅云函数可读写） |

用户注册后用产品账号登录 → 在「我的账户」页点「绑定高驰」走一次 OAuth → 之后你就能按需/定时拉他本人的数据。

### 11.2 技术栈（平台已有能力，全部国产）

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 前端 | 现有 `web/` 静态站（原生 HTML/CSS/JS + 本地 ECharts） | 部署到 **CloudBase 静态网站托管**（免费体验版对新建环境受限，见 §11.7） |
| 后端 | **CloudBase 云函数（Node.js）** | 承接登录校验、高驰 OAuth 回调、抓数、AI 复盘 |
| 用户认证 | **CloudBase 身份认证** | **邮箱验证码**登录：内置零配置邮件代发，也可自定义 SMTP（QQ / 163 / 腾讯企业邮） |
| 数据库 | **CloudBase 云数据库（文档型）** | 存用户、高驰授权、训练数据、额度；用集合「安全规则」做隔离 |

### 11.3 数据集合（CloudBase 云数据库，含安全规则）

| 集合 | 关键字段 | 权限（安全规则） |
| --- | --- | --- |
| `profiles` | _openid(=uid)、nickname、created_at | 本人可读写 |
| `coros_links` | _openid、region、coros_user_id、**enc_token / enc_refresh**、expires_at | **仅云函数**（客户端不可读） |
| `activities` | _openid、activity_id、sport、start_time、distance、duration、pace、hr… | 本人可读 |
| `metrics_daily` | _openid、date、training_load、hrv、sleep… | 本人可读 |
| `ai_keys`（可选） | _openid、provider、**enc_key**、masked | **仅云函数** |
| `usage_quota` | _openid、date、review_count | 本人可读计数 |

> 规则：`enc_*` 类字段（高驰 token、用户 AI Key）**永不下发前端**，只由云函数读写；其余集合靠**安全规则**（`doc._openid == auth.uid`）保证「每人只看自己」。

### 11.4 接口（CloudBase 云函数 + HTTP 访问服务）

- `GET  /api/me` —— 当前登录用户资料 + 高驰绑定状态
- `POST /api/coros/authorize` —— 生成高驰授权 URL（云函数注册/复用 client + PKCE）
- `GET  /api/coros/callback` —— OAuth 回调：用 code 换 token、加密入库、回跳账户页
- `POST /api/coros/sync` —— 按需抓取该用户高驰数据入库
- `GET  /api/dashboard` —— 返回**本人**看板数据（云函数校验身份）

### 11.6 决策（2026-10-09）

**已确认**：
- **后端/部署**：腾讯云开发 CloudBase（**弃用** Vercel / Supabase —— 用户无国外访问环境）。
- **登录**：邮箱验证码（CloudBase 身份认证原生支持，**无需自建邮件服务**）。
- **登录通信**：**服务端中转**（不依赖「WEB 安全域名」）——实测免费体验版**加不了安全域名**（点添加即弹升级），而**服务端调用认证 HTTP API 不校验来源域名**，故由后端代打。将来升级套餐后，前端可直接切回 SDK 直连（`web/auth.js` 顶部 `MODE` 改 `sdk` 即可）。
- **AI 费用**：**用户自填 Key 优先**（加密托管，兼容国内主流平台），**平台 Key 兜底默认关闭**（`PLATFORM_LLM_ENABLED=false`，绝不默默消耗平台额度）；仅当显式启用平台兜底时才用平台统一 Key，并按**每日额度**限流防滥用。
- **收费**：暂不收费，账号预留套餐/额度字段。

**下一步**：进入**阶段 C（阶段十一）**——云端抓数入库 + 看板改为读云端：用 `coros_links` 里已加密入库的高驰 token（云函数内解密）调用高驰官方 MCP 抓取训练数据，落到云数据库，看板读云端（安全规则隔离）。

- 数据有滞后时，点评前缀「（数据截至 MM/DD）」。

### 15.2 口径与取舍

- **窗口取"滚动 7 天"而非"自然周"**（关键取舍）：数据同步有滞后，"自然周"会让"本周"只剩半天，拿去和完整"上周"比会严重失真（首版实测：本周 5.0 km vs 上周 52.1 km，环比 -90%）。改为 **最近 7 天（`end-6`..`end`）vs 前 7 天（`end-13`..`end-7`）**，两段各完整 7 天、可比。`end` 取数据里**最新一条训练日**，故标题与点评口径统一为"近 7 天 / 前 7 天"。
- **变化列带单位**：跑量/时长用 % 环比；次数用 `+n`；配速用"快/慢 Ns"（快=绿、慢=红）；高强度占比用百分点 `pp`；心率用 `bpm`；短期负荷用 `+n`。数值 0 时显示"→ 持平"。
- **缺数据不臆造**：平均心率行、高强度占比行、短期负荷行**仅当两窗口至少一个有值时**才出现，否则整行隐藏；无 paces 时算不出高强度占比则不加该行。窗口内无任何活动 → 整卡 `hidden`，不显示空壳。
- **配速=加权配速**：`总时长 ÷ 总公里`（非各次配速的算术平均）；心率按**距离加权**，避免短距离拉偏。
- **短期负荷取窗口峰值**：该 7 天内 `trainingLoad` 的 `shortLoad` 最大值（代表这段时间最高负荷水位）。

### 16.2 佳明数据源方案（**关键待核实**）

> 佳明不像高驰那样给个人一个现成可用的**官方 MCP**；`claude-fitness-cn` 用的是**本地 stdio MCP 包**（`Taxuspt/garmin_mcp`、中国区 `BorisBW/garmin-mcp-cn`，`uvx` 运行），与本项目「HTTP 直连 + 零第三方依赖」的形态**不同**，故须先定路线。

| 方案 | 说明 | 优点 | 风险 / 代价 |
| --- | --- | --- | --- |
| **A. 佳明官方 Health API** | Garmin Connect Developer Program（OAuth 2.0） | 官方、合规、稳定 | 需**申请**（公司信息、按量计价）；面向平台，个人门槛高 |
| **B. 非官方 Connect 登录** | `python-garminconnect` 等社区库模拟登录 Garmin Connect | 个人即可用、字段全 | **第三方依赖**，违反「零依赖」红线；登录方式易被风控/失效 |
| **C. 参考项目 MCP 包** | 直接跑 `garmin_mcp` / `garmin-mcp-cn`（uvx） | 与参考项目一致 | 同为**第三方依赖**；且需改造为**本项目可调的形态**（我们不是 Claude MCP 客户端） |
| **D. 文件导入（兜底）** | 用户手动导出 FIT/GPX/CSV，写**标准库解析**导入 | 零依赖、零合规风险 | 手动、体验差；需自写 FIT 解析（二进制，工作量大） |

- **推荐（2026-10-11 核实后定）**：**本机自用走 B（非官方 Connect 库）**；**对外版暂不上佳明**。依据：
  - **A 对个人不可行**：Garmin Health API 属 **Connect Developer Program**——**只面向企业**、需申请 + 审核（可能按量付费），且 **2026 年新申请已暂停**（官方表单显示"Under Construction"、无重开日期），个人无门。
  - **B 真实可行**：社区库 `garminconnect` + `garth`（`garth` **原生支持国区 `domain=garmin.cn`**）是参考项目 `garmin_mcp` 及多个国区 MCP 的底层，**已有国区真机端到端验证**；字段最全（含**身体电量**、HRV、睡眠、训练状态等）。
  - **落地形态**：新增 `tools/source_garmin.py`，用该库登录取数 → 按 §16.3 统一模型输出（比再套一层 MCP 包更薄）。
  - **已知坑（先记）**：登录需**账号密码**（部分账号还要 MFA）；国区**切勿**把 `garminconnect` 升到 `0.3.x`（DI token 会失败）。
- **决策（2026-10-11 用户已确认）**：**采用 B**。等于在抓数脚本上**破例引入第三方依赖**——对该红线的**明确放行**，且**只限本机抓数脚本**，不进对外版后端。

#### 16.8.3 已确认的缺陷清单

**P0（算错 / 线上无效）**
1. **分段距离单位不一致**：高驰 `laps[].distance` 单位是**厘米**（100000=1km），佳明是**米**（1000=1km）。`raceSplits()` 按厘米除以 100 → **佳明比赛专项分析距离缩小 100 倍**（半程配速、R 值、CV、撞墙全错）；`drawLaps()`/`build_context()` 又按米除以 1000 → **高驰分段显示 100.00 km**、AI prompt 分段距离也错 100 倍。→ 统一在适配器层归一为**厘米**，展示层只做一次 cm→km。
2. **线上页脚「切换到佳明」按钮无效**：云函数 `dashboard` 未返回 `provider`，线上始终判为高驰 → 按钮点完刷新又回到高驰，形成死循环。→ 非本机（无本机文件）时隐藏切换按钮。

**P1（降级 / 口径不一致）**
3. 佳明 `trainingLoad` 只有 1 天 → 负荷图空白、近一周负荷环比为「—」、下周建议少一条依据。→ 逐日拉 `get_training_status(date)` 补 30 天（或由活动负荷自行累计 7d/28d）。
4. 佳明状态灯 `summary` 为空，且**佳明自带准备度（当日 25 分，偏低）未展示**，与「状态良好」并列易误导。→ 摘要补「HRV/静息心率/睡眠/身体电量」依据句 + 展示佳明准备度并标注口径差异。
5. `fitness.runningLevel` 佳明为 null → 顶部「跑力值 —」。→ 用已有 VDOT/预测反推（与高驰跑力值同量纲需先核对）。
6. `races.json` 只按账户码存，未带 `provider` → 切换品牌时比赛卡/倒计时串台。→ 记录加 `provider`，读取时过滤。
7. `dailyHealth.days` 字段类型不一致：高驰 `Steps:"0"` / `Calories:"0 kcal"`（字符串带单位），佳明 `7031` / `2162.0`（数字）。当前前端只用 `restingHr`，暂未爆雷，但后续健康卡必须先归一。

**P2（工程 / 安全）**
8. 项目目录**不是 git 仓库**（父级也没有 `.git`）→ `.gitignore` 目前不生效，佳明密码/令牌/训练数据实际上没有任何版本保护。→ 确认仓库位置或初始化。
9. 佳明账号密码明文存本机 `.garmin_secret.json`；建议改密码后重录，或改走官方 Personal API 免密码。
10. 云端 `activities` / `metrics_daily` / `profiles` **无 `provider` 字段** → 未来接佳明会把两品牌数据混在同一集合。需加字段 + 查询过滤 + 索引。

#### 16.8.4 「二选一」合并方案（统一契约 v2）

- **契约**：`dashboard.*.json` 顶层保留现有键，新增 `schemaVersion`、`capabilities`（能力声明）、`provider`。前端只按 `capabilities` 决定「显示 / 隐藏 / 降级占位」，不再写品牌 if-else。
  - 例：`capabilities: {recoveryPct:false, runningLevel:false, loadHistory:true, acwr:true, bodyBattery:true, garminReadiness:true, lapsUnit:"cm"}`
- **数据落点**：本机仍一品牌一文件（`dashboard.json` / `dashboard.garmin.json`）；云端统一 `activities/metrics_daily/profiles` 加 `provider`，`links` 集合由 `coros_links` 泛化（`provider: coros|garmin`）。

### 20.2 计算口径（关键）

- **即时跑力 = 丹尼尔斯 VDOT**（《Running Formula》第 3 版），用**公式直算**而非查表：
  - `vo2At(v) = -4.6 + 0.182258·v + 0.000104·v²`（v 单位 m/min）
  - `pctMax(tMin) = 0.8 + 0.1894393·e^(-0.012778·tMin) + 0.2989558·e^(-0.1932605·tMin)`
  - `VDOT = vo2At(距离m / 用时min) / pctMax(用时min)`
- **五区训练配速** = vVO₂max（VDOT 反解的最大摄氧速度，m/min）的**固定百分比**：轻松跑 69%~75%、马拉松配速 85%、阈值跑 90%、间歇跑 98.6%、重复跑 105.8%；配速(s/km) = `60000 / (百分比 × v)`。
- **赛事预测**：保持同一 targetVdot 不变，对目标距离（全马/半马/10K/5K）用**二分法**反解用时应为多少（用时越长 VDOT 越低）。
- **配速区间**：同一配速换算到 1 km / 1 Mile（1 Mile = 1.609344 km）/ 800 m / 400 m。
- **数字式输入**：`secFromDigits()` 从右往左两位一组（秒 / 分 / 时），如 `415 → 4:15`、`25920 → 2:59:20`。
- **步频 / 步幅互算**：步幅(厘米) = `(60000 ÷ 配速s/km) ÷ 步频 × 100`；反向解步频。

### 20.3 实现（前端纯函数，零第三方依赖）

### 22.2 比赛专项分析（联网调研后的核心维度）

把马拉松/路跑圈最常看的指标落成规则计算（数据来自该次记录的**分段 laps**）：

| 指标 | 口径 | 判读 |
| --- | --- | --- |
| 前半程 / 后半程 | 按**距离中点**切两半，分别算配速（与平均心率） | 直观对比前后段 |
| 正 / 负分割 | 后半程用时 < 前半程 → 负分割 | 负分割（后半更快）通常更佳 |
| 半程比值 R | 前半程时间 ÷ 后半程时间 | **R>1** 后半更快（负分割）；R<1 前半更快 |
| 配速波动 CV | 各分段配速的变异系数（标准差/均值） | ≤3% 很稳、≤6% 较稳、>6% 波动偏大 |
| 心率漂移 | (后半平均心率 − 前半平均心率) ÷ 前半平均心率 | 同配速下漂移小＝有氧底子稳 |
| 末段撞墙 | 后 20% 距离配速 vs 前半程配速 | 掉速 >12% 提示「撞墙迹象」 |

> 分段不足（<4 段，多为短跑）时降级为「整体指标」：完赛用时/配速 · 平均心率 · 最快 1km，并说明「没记录到分段」。

### 22.6 自动识别疑似比赛（补充：不用全靠手选）

> 用户反馈：「这么多数据，不至于连一条比赛都判断不出来，基本判断应该能识别出是不是比赛。」于是新增**自动识别**——不需要用户逐条挑，系统先从记录里把「像比赛」的挑出来。

**判断信号**（全部来自记录本身，无需联网）：以全体跑步计算基线——**配速中位数**、**距离 90 / 95 分位**。对每条跑步打分：

| 信号 | 加分 |
| --- | --- |
| 命中标准距离（全马 / 半马 / 10K / 5K，越难在日常跑到的距离权重越高） | +50 / +40 / +18 / +10 |
| 配速明显快于日常（≤ 中位数 ×0.80 / ×0.88 / ×0.94） | +30 / +18 / +8 |
| 超出日常长距离（≥ 距离 95 / 90 分位） | +20 / +10 |
| 户外（`sportType=100`） / 跑步机（`101`） | +5 / **−15** |
| 周末（周六 / 周日） | +8 |

**总分 ≥ 50 判为「疑似比赛」**，按分排序。呈现方式：

- 比赛卡空态直接提示：`系统已识别到 N 场疑似比赛，点右上「🏁 标记比赛」一键确认`。
- 点「🏁 标记比赛」弹窗分两段：**「系统识别到 N 场疑似比赛」**（每条带识别理由，如「半马距离 · 快于日常 · 超长距离 · 周末」，右上「**一键标记**」按钮）+ **「全部跑步记录」**（手动挑）。
- 「一键标记」后逐条生成完赛卡（默认名＝地点/项目 + 标准距离，如「半马」），可再点卡片改名。
- 已标记的自动从候选里剔除，不重复。

**实测（本机真实 296 条跑步）**：基线配速 5:52/km、距离中位数 6.6km、95 分位 20km；识别出 **14 场**疑似比赛，全部是距离 21.0–21.4km 的**周日**跑（配速 4:51–6:07/km），与「半马比赛」的典型特征吻合；一键标记后生成 14 张完赛卡并算出各场完赛用时，控制台无任何 JS 报错。

> 说明：识别是**启发式**（只用距离/配速/室内外/星期），目的是把候选缩到很小一撮、让用户「确认」而非「从几百条里找」；最终是不是比赛仍以用户确认为准（弹窗里可逐条点、也可只挑几场）。

2. 否则，**仅当** `PLATFORM_LLM_ENABLED === 'true'` 且配置了 `LLM_API_KEY`，才用平台 Key——此时**才**按 `usage_quota` 计/限流；
3. 否则返回 `{ ok:false, code:'ai_nokey', error:'…去「我的账户 → AI 复盘 Key」填写…' }`。

> **默认第 2 步关闭**（`PLATFORM_LLM_ENABLED` 默认 `false`）——即"不填就没有 Key"，**不会**用平台 Key，**不会**消耗平台 token。

### 26.1 用户看到

- 默认就是**简体中文**（不按浏览器语言猜）；切换过记在本机 `localStorage['coros:lang']`，下次沿用。
- 繁体版是**全文转换**：包括训练记录里的中文备注、AI 输出、图表 tooltip；英文版对未收录的文案保留中文原样（不做机翻，避免误译）。

### 26.2 实现（零构建、零第三方依赖）

- `web/i18n.js`（运行时）：
  - 语言判定 `?lang=` → `localStorage['coros:lang']` → `navigator.language`，写 `<html lang>` 与 `data-lang`；
  - `tr()`：繁体走 `window.COROS_S2T.convert`，英文走 `trEn()`（去/保留首尾空白 → 精确词表 → `PREFIX` 前缀规则 → `PAT` 正则模板 → 原样）；
  - `applyTree()` 用 `TreeWalker` 遍历文本节点并处理 `title/placeholder/aria-label/alt`；`MutationObserver`（childList / characterData / attributes，16ms 批量）跟随动态 `innerHTML`；
  - 跳过：`SCRIPT/STYLE/NOSCRIPT/TEXTAREA/PRE/CODE/CANVAS/SVG`、`#aiBox`、`#coachLog`、`.chat-bubble`、`data-i18n-skip`、`#i18nSwitch`、备案号链接；
  - `patchECharts()` 在脚本同步执行时就包裹 `echarts.init`，返回实例的 `setOption` 递归翻译 option 里的中文字符串；
  - `applyHead()` 处理 `<title>` 与 description / og 元信息。
- `web/i18n/en.js`：6 份分片翻译合并的 1368 条词表，冲突用 `OVERRIDE` 表定夺；备案号保留原文。
- `web/i18n/zh-hant-data.js`：`zhconv`（MediaWiki zh2Hant + zh2TW）+ 台湾 IT/跑步用词补充，只收 BMP 单字（避免 UTF-16 错位），词组按 2–4 字最长匹配。
- 引入方式：10 个 HTML 页在 `</body>` 前按序引 `i18n/zh-hant-data.js` → `i18n/en.js` → `i18n.js`。
- 发布：`tools/deploy_web.sh` 白名单加 `i18n.js`，并整体 `cp -R web/i18n`。
- AI 跟随语言：`web/app.js`（复盘）、`web/coach.js`（教练）在请求里带 `lang`；`web/serve.py` 的 `system_prompt_for()` 与云函数 `review` / `coach` 只替换「回答语言」一句，数据口径与四段结构不变。
